# 渣熊桌宠：第一版设计

## 1. 目标与范围

第一版是仅供用户本人在 macOS 使用的桌面桌宠。渣熊始终以透明、无边框的小窗口停留在桌面上；用户可以拖动它、点击它，并在饭点收到吃饭提醒。

第一版的体验目标是“有陪伴感，但不打扰”：桌宠主要通过动作和小气泡互动，不频繁抢占焦点或弹系统通知。

第二阶段才解决两台电脑之间的一对一配对与同步；当前不接入账号、云端服务或任何对象端功能。

## 2. 用户体验

### 2.1 桌面行为

- 启动后，渣熊显示在上一次停留的位置；首次启动默认位于右下角。
- 渣熊窗口透明、无边框、不抢键盘焦点。
- 用户按住渣熊主体即可拖动；放开后立即保存位置。
- 第一版本地预览中，用户双击桌宠可按“待机 -> 工作 -> 吃饭 -> 待机”循环切换，便于检查三段视频素材。
- 右键或菜单栏入口提供：暂停提醒、关闭桌宠、打开设置。

### 2.2 状态与动作

| 状态 | 触发 | 可见行为 |
| --- | --- | --- |
| 待机 | 默认及随机间隔 | 眨眼、发呆、伸懒腰 |
| 工作 | 用户点击“工作”或在设置中启用工作时段 | 抱着电脑、偶尔偷看 |
| 吃饭 | 午餐/晚餐提醒，或用户点击触发 | 吃饭动作与一句短气泡 |

第一版只使用本机时间；不读取用户正在使用的应用、键盘内容、屏幕内容或其他个人数据。

### 2.3 提醒策略

- 午饭和晚饭时，先让渣熊变成吃饭状态并显示气泡；默认不立即发 macOS 系统通知。
- 当前前端预览版已按本机时间检查 12:00 和 18:30，并在命中饭点时切换到吃饭状态。
- 用户点击当次吃饭提醒后，渣熊用短动画或气泡反馈，然后回到待机；这不是一个独立状态。
- 同类提醒在 30 分钟内不会重复；连续两次提醒未被回应时，才发送一次系统通知。
- “暂停提醒”会停止所有定时触发，但不会影响拖动与点击互动。

默认的饭点为 12:00 和 18:30；设置页允许用户后续修改。

## 3. 技术设计

### 3.1 技术选择

使用 Tauri 2 作为桌面应用外壳，前端负责渲染角色、动画和气泡；Rust 侧负责窗口、菜单栏、通知、设置持久化与本机定时任务。第一版只打包 macOS，但项目结构保持 Windows 可构建，以支持第二阶段。

### 3.2 组件边界

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| Pet Window | 透明窗口、置顶、拖动、窗口位置 | 业务提醒判断 |
| Pet State Machine | 在待机、工作、吃饭之间切换 | 保存用户设置 |
| Reminder Scheduler | 根据本机时间、暂停状态和防重复规则发出提醒事件 | 渲染具体画面 |
| Animation Player | 播放动作序列与气泡 | 选择何时播放 |
| Settings Store | 保存位置、提醒时段、间隔、暂停状态 | 云端同步 |
| Menu Bar | 暂停、设置、退出 | 角色动画 |

事件流为：`本机时钟 -> Reminder Scheduler -> Pet State Machine -> Animation Player / 气泡 -> 用户点击 -> Pet State Machine + Settings Store`。

### 3.3 素材策略与 IP 边界

用户提供的三段录屏作为第一版本地私用素材：吃饭、抱电脑工作、待机放空。开发原型直接使用这些本地视频来尽量贴近用户视频里的样子；不得把“渣熊”原始视觉素材打包为可公开传播、下载或销售的产品。若进入分享、发布或双人分发阶段，须取得相关权利授权，或改用原创角色资产。

## 4. 验收标准

在用户的 macOS 设备上，以下项目均可实际验证：

1. 桌宠启动后保持透明、无边框、置顶，且不阻塞正常打字。
2. 用户能把渣熊拖到任意屏幕位置；关闭再启动后位置不变。
3. 用户点击桌宠会得到随机动作或气泡回应。
4. 在测试用饭点下，桌宠会切换为吃饭状态；回应、防重复和暂停规则有效。
5. 连续两次未回应后，仅发送一条 macOS 系统通知。
6. 设置和菜单栏入口可用，且不依赖网络。

## 5. 后续阶段（不属于第一版）

第二阶段增加 Windows 构建和一对一配对。届时，“提醒对方吃饭”会被建模为一个明确的远程事件：本机点击 -> 经认证的同步服务 -> 对方桌宠接收 -> 对方显示吃饭状态。该阶段再决定配对机制、同步服务、隐私提示和失败重试策略。
